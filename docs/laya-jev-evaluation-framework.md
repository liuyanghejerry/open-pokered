# Laya MLX 与 Jev：20 分钟自主剧情探索评测

本轮回答一个具体问题：保留当前分支的策略层、动作层、候选生成、通用操作技能和记忆机制，只替换结构化判断后端，本地 Laya 与在线 Jev 在相同有效时间内分别能取得什么结果。它衡量整套代理系统使用不同后端的表现，不把一次游戏结果等同于模型能力排名。

## 1. 冻结条件与执行顺序

| 项目 | 约定 |
|---|---|
| 起点 | 每次独立进程、空存档，真实 NEW GAME；随机种子 42 |
| 总目标 | 当前自主控制器的主线目标：获得初始精灵、图鉴、八枚徽章、击败冠军 |
| 剧情路线 | 不调用 m01–m49 里程碑路线，不加载已有通关存档，不注入道具、经验或剧情旗标 |
| 执行技能 | 同一套寻路、交互、对话、战斗、练级、治疗、秘传机操作技能 |
| 引擎 | 同一 SHA-256 的二进制；`--speed 0`，只有控制器指令推进模拟帧 |
| 采集 | 不录视频；约每 0.5 秒采样一次状态；保留全部判断请求、结果、操作日志及最终截图 |
| 观测隔离 | 新增图鉴、经验和实时战斗队伍信息供评测器读取；从返回控制器的响应中移除，不改变传给模型的状态 |
| 时间 | 每个后端 1,200 秒有效墙钟；计时包括开局操作、规划、模型推断、执行和采集开销 |
| 初始化 | 模型加载及一次通用预热放在计时前，单独报告耗时与 Token；编译新输入形状等运行期开销仍计时 |
| 顺序 | 完整通关录制与视频渲染结束后，Jev → Laya 串行运行，避免两个实验彼此抢占资源 |
| 次数 | 各一次，预先固定；低进度、停滞或模型出错都保留为结果，不挑选最好的一次 |
| 停滞 | 只报告，不因后端不同增加特殊提示、修改候选或人工解围；最终由时间上限退出 |

策略层和动作层同时更换后端。调用方给出的状态对象、问题文字和候选构造规则相同；模型行为分叉以后，两条轨迹的后续具体输入自然不同。动作缓存、拒绝处理和常规恢复策略仍来自同一个控制器。

## 2. 模型与输入边界

Jev 固定为 `jev-1.13.0`，通过仓库现有 TypeSafe 客户端调用。Laya 按本机 `~/develop/laya-mlx/howto.md` 使用 Python 3.12 虚拟环境中的 `laya-mlx`，默认英文检查点 `aac6fef/laya-mlx`，revision `20aed815fc6acde75733882e7ec0e3f28aeb9717`，FP16、`compile=True`、`pad_to_multiple=16`、`cache_prompts=True`。现有控制器主要使用英文输入，因此本轮不切换 multilingual 检查点。

Laya 原生最大输入为 512 Token，问题及选项前缀预算为 192 Token；单个选项还会受到更细的裁剪。原控制器的长状态、候选剧情条件和战斗信息可能因此被截断。本轮保留其原生行为，并为每道问题记录：完整应用输入、实际编码文本、状态/问题/候选被删去的 Token 数。

**“相同调用方输入”不等于“模型实际读到了相同信息”。** 本轮结果包含上下文适配的影响。后续如需要比较判断能力，应另设共同压缩输入、较少候选的对照实验；不能只为 Laya 临时改提示后继续沿用本轮结论。

## 3. 时间与 RTT

```
有效耗时 = 原始墙钟 − 已测量并获准扣减的 RTT
```

Jev 每次 HTTP 尝试读取实际 HTTPS socket 的 macOS `TCP_CONNECTION_INFO.tcpi_rttcur`，单位由毫秒转为秒。每次最多扣一个 RTT，并且不超过该次请求耗时；整轮累计最多扣 300 秒。因此原始游戏运行时间最多 1,500 秒。

不扣除整个 API 请求时延，不把服务端推断、排队、重试退避、DNS 或 TLS 建连耗时自动当成网络 RTT。无法读取的样本扣减为零；若存在代理，socket 数值可能只反映连接到代理的链路，本轮也不猜测更远链路的耗时。报告同时展示原始墙钟、累计请求时延、RTT 扣减和有效墙钟。

控制器在指令边界和判断返回后检查预算；外部监督进程独立计时，防止内部无限循环或阻塞。到时先中断，8 秒后仍不退出则终止私有进程组，再等 2 秒强制结束。退出宽限期和最终诊断读取不计分。到时前发出、到时后才返回的请求保留成本记录，但不得再产生游戏操作。

## 4. 评测指标

| 维度 | 主指标 | 解读边界 |
|---|---|---|
| 剧情推进耗时 | 每个真实剧情目标首次观测满足时的原始/有效秒数；目标随时间的阶梯曲线 | 受采样间隔限制；未达到的目标写“20 分钟内未达到”，不伪造通关耗时 |
| 剧情进度 | 已完成目标名称、数量 / 11；徽章数量 / 8；最终地图和位置 | 目标数量不是剧情长度百分比；相同计数也可能走了不同路线 |
| Token 消耗 | 服务/本地库报告的输入与输出 Token，总调用次数、每层调用数；成功和失败调用分开 | 未返回 usage 的请求标为未知，不推算为零成本；不同 tokenizer 不可直接当作等价计算量；Laya 不生成文本，输出为 0 仍有推断成本 |
| 图鉴 | 已见 / 151、已拥有 / 151、拥有的全国图鉴编号 | 队伍数量不等于图鉴完成度；进化、赠送、捕捉按引擎真实记录计入 |
| 支线探索 | 预先声明的 11 项可选成就完成情况，首次观测完成时间；采样观察地图数另列 | 去过地图不等于完成支线；主目标仍为通关，因此不把支线低覆盖直接判作错误 |
| 队伍练度 | 全队物种、等级、经验、HP、状态、招式/PP；最高/平均/总等级 | 总等级会受队伍人数影响，必须连同成员明细解读 |
| 失败次数 | 代理报告战败、采样观察全队倒下、无效/受阻操作、被拒动作、模型错误、协议错误分别列出 | 类别存在重叠，不相加成一个“总失败”；观察全队倒下只是采样证据 |
| 金钱 | 初始/最终/峰值余额；观测到的正、负余额变化累计 | 正变化是采样可见收入下界；同一采样间隔内收入与支出可能抵消，不能宣称精确毛收入 |
| 停滞 | 连续 180 秒无新增旗标、地图、图鉴、等级或经验的区间 | 是疑似停滞，不自动等同程序死循环；不修改策略 |
| 执行成本 | 总模型等待、调用时延中位数/P95、实际模拟帧、动作数和缓存命中 | 总耗时不只包含模型推断；本机负载和热状态可能影响本地模型 |

可选成就：自行车、旧钓竿、好钓竿、超级钓竿、飞翔 HM02、闪光 HM05、格斗道场获赠精灵、捕获闪电鸟/急冻鸟/火焰鸟、拥有复活的化石精灵。使用真实旗标、背包或图鉴记录；具体机器可读目录在 `openpokered/evaluation.py`。这是明确的有限覆盖集，不冒充全部支线。

## 5. 可复核产物与运行

每轮输出 `summary.json`、`observations.jsonl`、`requests.jsonl`、`commands.jsonl`、`trace.jsonl`、`progress.json`、`supervisor.json`、`final-observations.json` 和 `final.png`。摘要记录代码文件哈希、提交、分支、二进制哈希、环境、初始化成本和退出原因。凭据不写入请求日志。

```bash
PYTHONPATH=scripts python3 -m unittest scripts/test_model_evaluation.py
cargo test -p pokered-app --lib --features debug-server evaluation_telemetry_reads_dex_and_experience_without_advancing
cargo build -p pokered-app --features debug-server

# 二者采用同一 Python 环境、同一 binary。输出目录必须尚不存在。
~/develop/laya-mlx/.venv/bin/python scripts/openpokered/run_model_evaluation.py jev \
  --binary target/debug/pokered-app --output .artifacts/laya-jev/jev \
  --env-file /absolute/path/to/.env
HF_HUB_OFFLINE=1 ~/develop/laya-mlx/.venv/bin/python scripts/openpokered/run_model_evaluation.py laya \
  --binary target/debug/pokered-app --output .artifacts/laya-jev/laya

# 报告环境需安装 matplotlib。
python scripts/openpokered/report_model_evaluation.py \
  --jev .artifacts/laya-jev/jev --laya .artifacts/laya-jev/laya \
  --output docs/laya-jev-evaluation-results
```

先进行单独标记的短预检，验证接口、只读采集和超时退出；预检不纳入正式结果。正式运行前固定源代码，不根据第一种模型的表现改变第二种模型的输入或技能。

## 6. 如何形成结论

优先比较 20 分钟终点及共同达到目标的耗时，再查看判断成本、队伍与资源变化，最后用真实请求和操作结果解释路线分叉、战败或停滞。保留具体失败案例和输入截断证据。两者都没走到的区域应写“本轮未覆盖”。

一次固定种子的比较只能作为案例；若要给出稳定性或平均性能结论，需要多个预注册种子、交叉运行顺序，并分别测试：共同短输入、仅替换策略层、仅替换动作层、两层都替换。不能把早期 20 分钟的收益外推为完整通关能力，也不能从模型概率推断它未输出的思考过程。
