# 驱动式 CLI 场景回归

使用实际 master 9fe81b59326ab720141ce7a82ca0d0b4a175ef14 构建的同一个 CLI，固定 seed42、speed0。未修改的 s05 在第 8 个球时错误耗尽轮询次数，背包还剩 12 个；s08 在 START 准备阶段发送短 A，没进入队伍；s09 丢失第一个 DOWN，实际进入 SAVE，却因断言太宽而当作已打开 OPTION。证据见 master-failures.json。

修正仅涉及 scripts/scenarios.py：捕捉按实际战斗背包消耗计数，按游戏帧设置超时，并让最后一个允许的投球结算完成；START 读取已有 field_menu.ready_for_input，在准备结束后操作，通过实际菜单项目／光标选择条目；s08 明确验证队伍与 EXIT，不再依次打开无关子菜单；s09 明确验证 options 屏幕，重开时尊重保存的菜单光标，验证具体文本速度值保留。没有修改游戏代码或跳过失败场景。

修正后的全部 11 个场景在相同游戏二进制、相同 seed42／speed0 下通过，包括捕捉、队伍、战斗胜负／逃跑、存档往返、菜单、选项和强制换人。after.log 保留完整输出，verification.json 绑定游戏可执行文件、实际构建提交和脚本哈希。本报告不证明完整主线或全量原作差异已经覆盖。测试脚本变更不改变产品画面，故无需产品前后截图。
