# GBA 软件复位验证

修复前，A+B+START+SELECT 只把画面切回标题。继续游戏会回到已存的地图位置，却保留刚买但未保存的精灵球和800元；再次复位后选 NEW GAME 仍复用商店地图，只把主角放到(3,6)。修复后通过 BIOS 重新进入卡带启动入口，重新加载 SRAM，继续游戏恢复1000元和空背包，新游戏进入卧室(3,6)。

本次实际验证使用正常 release ROM、libmGBA 0.10.5 内置 HLE BIOS及物理按键。没有使用运行时存档/坐标/金钱修改，也没有调用模拟器 reset 代替游戏组合键。唯一内部 reset 是每个独立实例的初次冷启动。SAV 由正式 codec 在启动前构造，所有复位前后完整32768字节一致。

Continue 背包前后图来自完全相同的 `continue-inputs.json` 63段按键指令，总9369个硬件帧，截图都在frame9369；frame5740组合键前画面逐像素一致。两边 CPU 指令数量不相同。NEW GAME 组对照完成介绍后的相同游戏阶段，两边最后均等待400个中立硬件帧，绝对帧数不同。

测试：App default/debug计数器和平台复位测试及相关soft_reset共28次具名执行通过。正常 GBA release 构建通过。另实际完成普通场景、START菜单、战斗、无效SRAM、新游戏和重复复位。完整轨迹在第二次场景复位及战斗复位分别记录32个连续硬件 VBlank 的全白画面及物理声音关闭，随后确实执行 ROM/BIOS 启动和构造函数。

新增视觉控制里有一次额外只读断言写错字段：把 Inventory.max_per_slot 的 Some 标记当作背包长度。原 wrapper exit1 与原始记录保留；该断言之前空背包截图、1000元和SRAM相等均已完成，正常ROM没有修改或因该断言重跑。首次战斗控制只按32个硬件帧，对应14次App轮询，尚未触发；持续按住直到16次实际轮询后完成复位，没有放宽产品阈值。

这不是实体 GBA 或任天堂 BIOS 测试，也没有证明所有原作 Joypad 消费者的轮询节奏已经统一。精确来源、哈希、已完成验证和未验证边界见 `validation.json`。本地详细原始证据不随PR上传大ROM/ELF和重复帧。
