# 双方同时倒下：演出与台词验证

自爆、大爆炸或致命反作用力让双方同时倒下时，原作先进入哪个昏厥处理程序，会改变后续退场、叫声和台词。本修复用实际 `Fainted` 事件的处理顺序和完整队伍存活情况决定演出；不从本地化文字、招式名称或最终两只 HP 猜测入口。

固定原作：`fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c` 的 [engine/battle/core.asm](https://github.com/pret/pokered/blob/fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c/engine/battle/core.asm)：732–813、969–987、1027–1044 行。下表中的“后备存活”指我方完整队伍中仍有任意宝可梦 HP 大于 0；野生战敌方退场按原作使用胜利音乐，训练家战使用 Fall/Thud。

| 实际先进入的处理程序 | 后备存活 | 原作结构动作和声音 | 昏厥台词 |
|---|---|---|---|
| 敌方先倒下（玩家出招后自身也倒下） | 否 | 敌方退场及声音完成，再让我方无叫声退场 | 两句都不显示，随后黑屏 |
| 敌方先倒下 | 是 | 同上 | 两张图都退完才显示敌方台词 |
| 我方先倒下（敌方出招后自身也倒下） | 否 | 我方退场、叫声和台词，然后黑屏；不进入敌方昏厥程序 | 仅我方 |
| 我方先倒下 | 是 | 我方退场及叫声/台词，再进入敌方退场及声音/台词 | 我方后敌方 |

单方倒下、残余伤害和 Link 保留各自既有路径。新增快照字段有旧档默认值；普通文本页的 `None` 位置也完整恢复，避免首次测试发现的 FIGHT 文本快照回归。

## 复现材料和输入

`only-geodude.sav`：常青森林玩家(2,19)，向上与(2,18)训练家交互；Lv21 小拳石 HP1/54，自爆在第四招。`healthy-reserve.sav` 额外有健康 Lv5 波波。两档初始钱1000、硬币0、训练家未战胜。它们沿用原物理存档构造/校验和/导出回读证据，未在运行中注入战斗或修改状态。

`fixed-buttons.json` 是两种场景共同使用的原3572帧 `Vec<Vec<String>>` 字面向量，只含空帧和 A/B/START/UP，原样复制。它包括正常语言页/Continue、继续游戏默认朝下后的转向和交互、FIGHT/向上回绕选第四招、预先固定的收尾输入。没有根据候选状态决定按键、延长尾部、试种子或搜索。每次构造普通 `PokemonGame` 后只设置一次启动种子42，之后只传正常 `InputState`。

`faint-witness.rs` 是实际分别链接前后正常 App `--lib --features debug-server` 库的同一份源文件。每帧一次真实 `Game.update`、一次160×144 `Game.draw` 和一次1470个 f32 的44.1kHz立体声 PCM 拉取。后者只推进 APU，sequencer 仅由正常 Game 更新；记录通道身份、状态、原始 PCM、每帧哈希/RMS/峰值及整文件 SHA256。这里是音乐/声效混合的无设备 PCM，没有把它称为孤立叫声波形或扬声器实录。没有 debug RPC、warp、运行态 restore、结果/HP setter；`BattleSnapshot::capture` 只作不可变观察。

前后正常 App 的实际 `-vv` 调用选出七项 extern；完整1871依赖逐项核对后链接并冻结两个 ELF。必要恢复基线库一次；候选库全字节复用。全部输入、状态、1732 PNG 和 PCM 原件保留在本地证据，提交只包含本目录小型复现材料和六张对照图。完整 SHA 和实际来源见 `provenance.json`。

## 原生结果与同帧截图
