# 免疫攻击的失败提示

原作的 PrintMoveFailureText 先读取最后匹配属性行留下的显示字节。零值显示 “It doesn't affect <TARGET>!”；非零值进入未命中分支。因此地震打电／飞行的闪电鸟、虫／飞行的巴大蝶都不造成伤害，却分别保留 20、5 并提示攻击未命中。地震打波波、撞击打耿鬼保留 0，提示无效并写出实际目标名称。

命中检查前记录本次出招的显示字节，避免命中率失败跳过伤害回调后丢失信息，也避免对方随后使用属性转换改变先前提示。伤害回调继续记录自己的实际结果；明确的 Missed 事件仍保留作用。双方名称由既有 BattleNameContext 提供。

verification.json 记录 4 个原作 CPU 例程控制、5 个原生修复前案例，以及核心／应用回归的范围。原作例程控制不等于整场战斗、声波或逐周期验证。修复后 5 个实际 CLI 案例以相同存档、相同输入时间线复查通过；11/11 场景与 GBA 性能基线通过。master 与 PR 分支的三组同输入／同帧截图已完成，见 screenshots.json；初始画面、状态、存档哈希一致，最终帧号一致，目标 HP 不变。

截图工具 capture.py 使用 fixtures/ 中的两个隔离存档和 capture-plan.json 的固定输入序列。先在 master 构建 CLI，记录可执行文件身份 JSON，再以 --mode before 运行；随后在 PR 分支构建并以 --mode after 运行。两次必须复用相同的 capture.py 和 plan，--workspace 指向实际构建检出，--identity 指向构建身份记录，--output 使用两个新目录。工具验证截图不推进帧、输入帧匹配、消息正确且免疫目标未掉血；比较初始 PNG／状态和最终帧号后再提交前后 PNG。
