# 图鉴运行的有限来源恢复（2026-10-01）

目标仍为实际合法登记 124 种；50 种检查点不是完成证据。

审计发现 resume-24 在 521.427 秒首次获得 `EVENT_BEAT_ZAPDOS` 和
`__OBJ_HIDDEN_POWER_PLANT_OBJ_9`，但没有登记 Zapdos。先前两次 RUN
（36.564、41.504 秒）均为原生 `won: false, escaped: true`，没有获得事件标记。
因此，“RUN 保留来源”成立，但不能据此认定整个后续运行一直保留来源。

真正的问题发生在最后一颗 Great Ball 耗尽之后：菜单层仍提供捕捉准备，
招式层却因没有球而取消捕捉意图，改用最大伤害问题；随后两次选择
Flamethrower，最终原生 `won: true, escaped: false` 消耗闪电鸟。
这不是逃跑结果映射错误，不应通过更改原生击败标记的语义来修复。

修复将有限来源保留意图独立于球库存/当前箱容量。经过脚本语义证明可以
RUN 重试的未登记来源，在没有可用球或容量时不提供 FIGHT；若已进入招式
菜单，以真实 B 输入取消，返回菜单比较 RUN 和恢复操作。普通训练家、
不可捕捉幽灵的处理保持原样。

回归包括无球/箱满单元测试，以及 s15、s18 原生静态闪电鸟场景，验证
RUN 后未登记、未设置击败标记、切换地图后仍能重新触发同一来源。
这些隔离种子场景只验证修复，不计入正式图鉴或正式录像。

正式恢复选择真实 resume-23 检查点（41 种，闪电鸟击败标记未设置）。
该检查点是在战斗中停止的开发存档；SRAM 不保存战斗运行时，CONTINUE
返回保存的地图状态，并非逐帧恢复原战斗。后续新增种类必须重新通过正常
游玩获得。resume-24 至 resume-32 的失败分支及录像保留用于审计；不得将
其中登记种类叠加到恢复分支，也不得把失败分支拼接为无回退的成功过程。
最终成功页面/MP4 必须明确分支与检查点，并通过原生 124 种完成和独立
CONTINUE 验证，才可发布。

## 有限来源早停检查

控制器现在根据获取图和编译脚本检查未登记的纯静态物种：只有所有已知
来源均被已观察到的、脚本没有清除路径的战后完成标记阻断，才记录
`finite_collection_source_lost` 并保存失败检查点。普通临时隐藏、尚未打开
的通道、未知脚本或另有野生/赠送/进化来源均不构成这项证明；已登记的
物种也不会误报。该检查不把目标自动缩减为 123。

隔离复制两份真实存档并通过原生 CONTINUE 验证：resume-23 恢复 41 种、
闪电鸟标记未设置，检查放行；resume-32 恢复 50 种、闪电鸟标记已设置而
未登记，检查明确报告 Zapdos 的 PowerPlant/talkZapdos 来源耗尽。原存档
不改写，隔离过程只读取状态和脚本语义，不算正式游戏进度。

检查在后续启动加载；已运行的 resume-33 不热替换策略、不为加载这项
预防性检查而中断。运行中的正式分支仍从 trace 逐项检查有限来源结果。
