## Jev：能持续推进，但战斗准备消耗明显

有效时间 3:20.792 获得第一枚徽章，10:55.615 获得第二枚，13:13.685 获得第三枚。主力从 5 级练到 37 级，采样访问 37 张地图，累计执行 483 个语义操作、复用选招缓存 294 次。

12 次代理报告战败中，小刚 1 次、小霞 11 次；不是 12 个不同故障。阶段中余额降至个位数，随后才因胜利回升。重复挑战会获得经验，因此“无新增状态 180 秒”的停滞判据没有触发，但主线效率仍可能很差。后续应同时评估每个主线节点的耗时、重试次数、训练投入和资源损失，不能只用停滞标记筛查低效行为。

约 0.5 秒的采样只捕获到 4 次全队 HP 归零，少于战败事件日志的 12 次，说明短暂状态会被漏采。失败表已分开列出，二者不能相加。另有 8 次旅行受阻、0 次协议错误和最后 1 次服务错误。最后的位置在枯叶道馆外，返回治疗路线时还遇到需要居合斩清障的情形；真正终止控制器的是随后请求的 HTTP 402，不能误判为树木障碍导致系统无法继续。

累计 API 请求时间 717.627 秒，仅扣除 239.707 秒实测 RTT。服务推断、排队等没有整体免计。额度中断后剩余 401.975 秒有效预算没有被使用；本轮不预测其本应取得的进度，也不以新请求重试掩盖中断。

## Laya：请求有效，但没有形成首个可执行动作

Laya 按 `~/develop/laya-mlx/howto.md` 使用 `laya-mlx 0.1.0`、英文检查点 `aac6fef/laya-mlx`，FP16、本地离线推断及原生截断行为。3 次请求全部成功返回，没有推断异常或协议错误。

实际链路为：

1. 首次策略输出 `none=44.93%`、博士出场子目标 `30.30%`、包裹子目标 `24.77%`。共用控制器原有的条件选择规则发现非 none 总质量为 55.07%，因此选择博士出场子目标；这一步不能描述为 Laya 直接选择了博士。
2. 动作层收到 `travel_to:PalletTown`，给该动作 18.43%、none 81.57%，拒绝执行。没有发生语义游戏操作。
3. 策略层评估剩余包裹子目标，给 none 64.05%，随后停止。最终仍位于 `RedsHouse2F (3,6)`。

最初两次应用层请求与 Jev **完整 SHA-256 相同**。Jev 对首次策略的博士目标给 86%，对前往真新镇的动作给 100%；两种后端在真正相同的应用输入上发生分叉。它们仍未必读到相同的有效信息。

### 不只是 512 Token 总上限

| 调用 | 状态 Token：原始 → 保留 | 实际编码总 Token | 候选裁剪 |
|---|---:|---:|---|
| 首次策略 | 350 → 316 | 512 | 两个剧情候选分别 132 → 48、113 → 48 |
| 前往真新镇动作 | 163 → 163 | 307 | 动作描述 149 → 48 |
| 剩余策略 | 355 → 316 | 512 | 包裹候选 113 → 48 |

第二次请求总共只有 307 Token，状态完整保留，但动作候选仍因原生单选项限制删去了 101 Token。实际编码文本停在 `"produces": ["flag",`，后续剧情效果和导航说明未进入模型。因此仅扩大总窗口，未必能解决当前表示方式的信息损失。

这是截断的直接证据，**不是截断必然导致拒选的因果证明**。还可能涉及任务表述、模型判断或拒选概率的校准。不能把输出结构兼容理解为可以直接替换，也不能从这 3 次判断推断 Laya 普遍无法玩游戏。

Laya 请求时延中位数约 98 ms，Jev 约 823 ms；但调用集合和实际信息量不同，Laya 又没有完成游戏目标，所以不能据此声称它的任务效率或单位 Token 收益更高。Laya 的输出 Token 为零表示不生成文本，仍有本地前向计算成本。

## 下一轮怎样获得更有解释力的结果

| 工作 | 目的 | 实验约束 |
|---|---|---|
| 补足 Jev 服务额度后重新登记一对运行 | 获得完整预算的可比较终点 | 本轮保留为中止案例；新目录、固定版本，不覆盖或只挑最好成绩 |
| 为两个后端共同设计紧凑输入 | 验证候选关键条件完整可见后的表现 | 状态、问题和每个候选均按原生预算压缩；先验证信息完整性，再进行独立对照 |
| 单独检查拒选规则 | 区分原始模型分布和控制器条件选择的影响 | 使用预先标注的可执行 / 不可执行候选集合，不只调整到某一次游戏能够出门 |
| 分别替换策略层和动作层 | 定位路线规划与局部操作的贡献 | 其余输入、技能和资源预算保持相同 |
| 多个预注册种子、交叉运行顺序 | 测量波动与稳定性 | 开发探针、正式评测、外部服务中断分开统计 |
| 增加明确的支线 / 图鉴探索目标 | 让支线指标真正参与决策 | 与本轮“以通关为目标”的成绩分开；去过地图不等于完成支线 |

外部时间监督、RTT 记账、原始输入与实际编码留档、只读图鉴/经验采集都已具备。两轮正式运行都提前停止，所以正式成绩本身没有触发 20 分钟强制截止；预算退出机制另由短预检和测试验证。后续仍需在完整预算和重复运行中检验这些机制。
