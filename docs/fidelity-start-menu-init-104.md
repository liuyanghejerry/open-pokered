# START 菜单首次输入与音效时序（104）

从场景打开 START 菜单时，原作先完成 DisplayTextIDInit，再执行 DrawStartMenu，随后才读取菜单输入。旧实现立即接收输入，因此初始化期间的一帧按键也会移动光标或关闭菜单。

本次修复只针对场景进入菜单：保留进入前场景 Joypad 样本，等待 23 个硬件帧后读取当前持续按键；已经松开的短脉冲不重放，进入菜单前已经按住的按钮也不作为新的菜单按键。START 音效在第 20 帧调度，菜单接受 A/B/START 时补上原作的 PressAB 音效。debug get_state 的 input_ready 为只读观测。

## 原作依据与验证

原作固定为 pret/pokered fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c。3F 巨石入洞案例的 MoveSprite 在 t3，洞事件与 CUT 音效在 t73，DisplayTextID 在 t74，START 音效与 DrawStartMenu 在 t94，首次菜单 Joypad 在 t97。输入窗口探针覆盖 t85、94–100 的单帧 Down，以及初始化期间持续 Down/Up/A/B，另测已经随 START 按住的方向/A。原作和复刻各重复两次。30 个对应边界案例的菜单选择和音效调度一致，复刻每次 201 帧 PNG/JSON 重复一致。

原作 START/PressAB 音效编号 143/144，对应复刻按名称索引的 62/63。最初直接比较编号的汇总打印 None，保留该错误汇总并另存正确映射结果。这里证明的是音效调度，不宣称 PCM 波形一致。

四个推石方向和 Victory Road 3F 入洞共五种无菜单案例，每种重复两次、201 帧，逐帧 RGB 与相同输入的原作一致。该结果不能扩展为菜单文字或布局一致。
