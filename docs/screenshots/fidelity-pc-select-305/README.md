# Player PC SELECT sorting

Based on actual master a7d4731 after the independent SRAM import fix #175. Withdraw, Deposit and Toss item lists support SELECT marking and physical-slot sorting. Different items swap; same-kind quantities merge into the second slot, capped at 99 with excess in the first. Same-slot and CANCEL selections retain the mark; B exits and quantity cancellation clears it. Sorting preserves the other inventory and does not invoke ordinary SAVE.

SELECT uses the original 30-frame first hold delay and 5-frame repeat counter. The counter advances through the 20-frame sorting guard and 6-frame list reload. Same-slot SELECT repeats also reload for six frames, discarding short keys inside that guard. Cached rendering retains the first slot's hollow arrow when the active cursor moves away.

19 original emulator scenarios and actual native host scenarios repeat twice byte exactly. Inventory matches the original at every recorded frame; final list cursor/scroll match for the 15 tap/control scenarios, and cursor/scroll match at every frame for the 4 held scenarios. Native fixtures use public PokemonGame/PcScreen constructors, persistent InputState and actual Game.update; full Game.draw is compared with cached RenderSession every frame. These are controlled PC fixtures, not natural boot/playthroughs. The 15 baseline before/after fixtures use identical helper source; the four held fixtures run on the candidate and are compared directly with the original; the after-only fixed feature reads the public marked-slot getter for recording. Optional SAVE and reload paths are disabled for the comparison captures.

Four actual-master/candidate screenshot pairs show marking, Deposit sorting, duplicate-slot merge and quantity overflow at matching menu frames. Full debug app/core regression: 78 frozen programs, 3703 passed, 0 failed, 76 ignored. Fresh CLI m01–m03 and separate-process s07 pass. Fifteen controlled sorting scenarios exit the PC using B, open START/SAVE and save with A; a separate process uses actual CONTINUE prompts from a controlled MainMenu and verifies both inventories' physical order and quantities. Private SRAM/flags remain local.

The archive contains deduplicated PNG frames, controlled input/inventory records, scripts, source excerpts and full regression logs, verified byte exactly after packaging. It contains no ROM, SRAM, emulator state, private save snapshot or executable. PNG paths reconstruct via png-files.json and png-blobs.

General directional held repeat without SELECT, initial item-list sampling guards, other redraw guards and broader story/function coverage remain under separate audit. Source PPU-exact visual timing and whole-game equivalence are not claimed. Fonts, Chinese, pinyin IME and dialogue layout remain outside the goal.
