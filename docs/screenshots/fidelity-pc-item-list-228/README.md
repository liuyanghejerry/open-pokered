# PC 物品列表 A+B 优先级

原作 `home/list_menu.asm` 的 `DisplayListMenuIDLoop` 先检查 A，再检查 B。存入、取出、丢弃三条受控路径均以两份完整 ROM 录制确认：同时按 A+B 后选择物品，打印数量提示，然后进入数量菜单。

实际 master `ab9a272` 中 PC 的 `update_item_list` 优先处理 B，返回玩家 PC 菜单。修复仅让同一帧有 A 时不执行取消分支；确认菜单的 B 优先级不受影响。

三组前后截图均来自实际 PC 隐藏事件及菜单输入，使用同一受控库存（背包/PC 各四瓶伤药）、位置、随机种子和输入，在同时按 A+B 后第 20 帧截取。每侧 3 × 61 帧 × 2 份录制；每帧缓存画面与完整重绘全像素相同，同侧两份 PNG/完整原始 JSON 逐字节相同。原作录制按键保持两帧；复刻验证一次按下沿。未宣称两个运行时的完整开机、PC 打开时序或绝对 PPU 帧相同。

`evidence.zip` 保存 5418 张原始 PNG 的无损内容去重索引、原始状态/原作调用钩子、源码引用、夹具和运行脚本、源码与冻结测试二进制哈希及日志。`png-files.json` 映射每个原始相对路径到 `png-blobs/<sha256>.png`，每张图都重新读出与原文件逐字节比较。未包含 ROM、模拟器状态、SRAM 或可执行文件。
