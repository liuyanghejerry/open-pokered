# 停步后转向

原作 `home/overworld.asm` 的 NoDirection 分支置 `wCheckFor180DegreeTurn=1`，记录上次停下的方向；输入不同方向时消耗第一次场景更新，只转身并调用 NewBattle，然后返回循环。下一次场景更新才进行碰撞、行走和 UpdateSprites。这个检查与当前可见朝向不同，CONTINUE 可重置朝向而保留停步方向。

原作自然进入宝可梦中心的状态位于 3,3，朝上、停步方向 Up。无内存写入，空输入 120 帧后按住 Down 12 帧、释放 8 帧，重复两次完全一致：第 1 帧处理转向，步数仍为 0，第 3 帧步数变 7 并起步。

复刻使用 master `4a4bbbdbebbda5ee715f6bed4b2d4c9604145306`，相同地图、坐标、朝向和种子 0；从 3,4 用实际 Up 输入走到 3,3，然后相同空输入/Down/释放。旧版第 1 帧开始行走，修复版第 3 帧开始，全部 20 帧坐标与原作一致。逐帧同步输入明确检查 frame_count 每帧恰好增加 1。

前后截图均为实际帧 140（Down 输入相对第 3 帧），前者已提前滚动场景，后者刚开始正确的行走。触发前帧 136 的 PNG 完全一致。两边各录制两次，156 个 PNG 和帧清单共 157 个文件分别重复完全一致。

修复保存独立转向检查位到帧级快照，旧 JSON 缺字段时默认关闭；随后 NoDirection 正常重新置位。脚本移动不使用该物理输入检查。转向样本仍保留原作的遇敌检查，但不运行 NPC UpdateSprites。测试覆盖不同停步方向、相同方向、朝向与停步方向不同、FLASH 后转向以及快照恢复。

坐标与移动时点已核对；未声明完整原作/复刻 RNG 轨迹或逐像素视觉一致。

最新版引擎下完整核心 40 个测试集、3,239 项测试以及 41 个应用测试程序通过。开机到 m06 的实际输入回归通过初始宝可梦选择、昵称确认和第一次劲敌战，最终 OaksLab 5,6，队伍 1。回归驱动只在普通场景中保持 A/START 跨过采样等待；菜单/对话保留原先单帧边沿。转向驱动核对实际朝向和坐标，选择菜单/战斗断言未放宽。

自行车道在 JoypadOverworld 中先将无按键转换为 DOWN，再记录方向或处理 NoDirection。复刻也在有效输入确定后记录停步状态，自动向下移动不会错误地置转向检查或记录停步。新增测试验证首次自动 DOWN 立即行走且检查位未置位。完整核心与应用回归通过；普通中心转向的 20 帧状态和 157 个录制文件与修正前保持逐字节一致。
