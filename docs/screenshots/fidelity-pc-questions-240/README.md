# 物品 PC 提问修复证据

基底：当前 master `3badf5a7359c93e684f4d8ef7d5329a83fe28da2`。候选只修复玩家物品 PC 的操作、取出、存入、丢弃提问及其取消后重新显示。

原作依据：pret/pokered `fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c` 的 `engine/menus/players_pc.asm`、`home/list_menu.asm`、`home/print_text.asm` 与 `data/text/text_2.asm`。初次进入的提问继承 NO_TEXT_DELAY，3 帧后自动 DONE；选中物品或取消列表清除该标志，因此取消数量后重新显示列表提问、退出列表后重新显示操作提问，按当前文字速度逐字打印，无需额外确认。列表绘制后重新设置该标志。

原作三个速度 × 三种操作，各录制两遍。逐字数分别为操作 22、取出 28、存入 27、丢弃 29（不计换行控制码）。延迟打印第一个字在相对 PrintText 第 3 帧，DONE 在 `3 + 字数 × 文字间隔`；间隔为 1/3/5。原作帧与复刻按 PrintText/阶段入口对齐，用于校验提问文字和逻辑交接，不宣称 CPU/PPU 的绝对时间相同。

实际 PokemonGame 通过常规按键从隐藏 PC 进入玩家 PC，没有直接设置 PC 阶段。控制夹具将背包和 PC 药水各设为 4；这是种子场景，不是自然获得物品的主线通关。三种速度 × 三种操作，分别捕获初始操作提问、初始列表提问、取消数量后的列表提问、退出列表后的操作提问。实际 master 与候选使用同一测试输入，每侧录制两遍；所有状态 JSON 和 PNG 都逐字节一致，每帧缓存渲染与完整重绘逐像素一致，库存不变，没有生成存档。

78 个单元/集成测试程序：3673 通过、0 失败、76 忽略。忽略的捕获测试通过上面的单独录制运行。旧数量提问、确认保护、库存事务和缓存回归保留。主分支使用同一规范测试在缺失初始提问处失败，且已通过库存/路径设置检查。

前后 PNG 为相同阶段、输入相对帧的实际 master/候选画面。`evidence.zip` 含原作记录、两侧全部录制、源码、测试日志和摘要；PNG 按 SHA-256 去重，`png-files.json` 将原始路径映射到 `png-blobs/<hash>.png`，归档逐文件回读验证。ROM、模拟器状态、存档和可执行文件不公开。

本修复不覆盖原作菜单额外输入等待/连按、全部 PC 消息/音效或全游戏通关。字体、中文、拼音输入法和对话框布局不在长期差异目标范围。
