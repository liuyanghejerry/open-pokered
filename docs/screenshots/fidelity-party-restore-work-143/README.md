# 菜单返回：精灵重载工作量模型（未接入恢复流程）

退出队伍菜单时，原作先变白、重载地图精灵、重载玩家与文字图块，再重画 START 菜单并读取输入。当前运行时过早恢复输入，短按 DOWN/A 可以打开背包；原作会丢弃这两个短按。本批只实现重载周期模型，尚未修复这个输入问题。

`sprite_reload_cycles` 根据室内精灵槽、室外固定精灵集、重复图像、VRAM 槽分配和分区道路执行路径计算 CPU 周期；不复制像素，不加载 ROM，不按地图编号指定等待帧数。涵盖 `InitMapSprites` 入口至 `EnableLCD` 入口，包含返回调用者的换银行代码。周期还需要与 CPU/PPU 相位组合，不能直接视为硬件帧数。

| 实际原作场景 | 预测和实测 CPU 周期 |
| --- | ---: |
| 常青市 | 219336 |
| 冠军之路 1F | 56940 |
| 冠军之路 2F | 106304 |
| 冠军之路 3F | 59316 |
| 玩家卧室 | 1184 |

五个场景共有 405 个独立原作 LCD 帧，各重复录制两次，JSON、输入 CPU 状态和 PNG 完全一致。场景继承此前固定的 SRAM/状态；冠军之路场景有受控位置，卧室继承正常 warp 管线的受控场景，不能当作普通行走到达的证据。

另外 496 个诊断配置覆盖全部 37 张室外地图、20 号道路特殊分区、不同室内精灵/重复图像配置。在 `InitMapSprites` 入口受控修改地图、坐标、精灵数量和图片 ID 的 RAM，保留原作 ROM 指令，使用原作模拟器测量周期。它们证明工作量计算，不证明正常剧情或行走。

Rust 的 501 个配置全部匹配，两个单元测试和 `no_std` 编译通过。第一次诊断生成器误含原作表外的 ID73，测试正确报错；已限定原作有效的 72 个 ID，重新生成全部配置，并在原作模拟器再次验证。失败日志保留在证据包中。

`evidence.zip` 以内容哈希去重保存原作记录、CPU 入口状态、诊断配置、预测工具、实测结果和日志。`manifest.json` 映射原始路径，每个对象的 SHA256 均已重新验证。无需引入 ROM 图块或指令数据到生产代码。

剩余工作：恢复状态机、CPU/PPU 相位、变白/图块传输阶段、输入门禁与去抖、NPC 重载及快照/缓存验证。PR 保持草稿。该模型尚未调用，因此本提交不改变玩家可见帧。
