# NPC 字体遮挡及 START 关闭恢复（121–127）

原作依据：pret/pokered `fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c`。实际 master 前图为 `31b1eda3112514d6bc803af559ec7f7c9e20374f`；后图对应本目录 provenance.json 记录的七个工作区源文件哈希。没有把旧提交 CI 或旧通关证据当作当前修复验证。

## 行为

START 前先执行一次 NPC 更新。字体加载时，窗口外 NPC 改为站姿，保留步行剩余计数及子帧；被字体覆盖的 NPC 隐藏，并保留动画阶段。超出原作坐标可见范围的普通 NPC 暂停移动。玩家行走时保留 NPC 完整图像索引，包括隐藏值 `$ff`。

关闭 START 的恢复按原作图形传输执行：32 个文本框 tile 的五帧复制、隐藏窗口的一帧、每种不重复的行走 sprite 上半部 12 tile 的两帧复制、玩家两个 12 tile 图块的四帧复制，然后才更新 NPC 和返回场景。室外使用原作 sprite-set / split-map 数据，室内去重 NPC 图片 ID（包括隐藏槽）；没有给具体地图硬编码总等待帧。常青市 28 帧，交换中心 12 帧。

独立 NPC 阶段、子帧、两级 OAM 姿势及恢复进度保存到 JSON；旧 JSON 字段默认兼容。普通 NPC 使用延迟姿势渲染，缓存键追踪实际姿势；脚本人物仍使用现有特殊路径。

## 对照方法与边界

三组手工控制的常青市 NPC：窗口外 x19、窗口内 x22、屏幕外 x27，统一 y29、向下、remaining12；原作 phase1/intra0，原生由 remaining12 推导相同阶段。四个真实硬件预热帧，随后 START 在 t0–39 按住，B 在 t50–51 按住，没有方向输入。玩家 map1 (20,30)。这是中途行走状态对照，不宣称来自自然随机行走。

原生引擎在起步时预设之后的 idle delay，原作在结束时选择。手工构造中途状态必须补齐该预设：窗口外为原作录得的 54，窗口内为 27；屏幕外不完成这一步，其 delay 不参与本段对照。最初缺少预设的夹具在 t97 提前开始下一步的失败日志保留在工作证据目录，未修改生产 RNG 来凑测试。

每组原作录制两次，RAM 与 PNG 完全一致。每组 master/后图也各录制两次，101 帧 RAM 与 PNG 完全一致。后图三组共 303 帧 NPC 不透明姿势、位置、可见性与原作一致；窗口外 101 帧 x48..64/y40..76 完整 RGB 区域也一致。未声称整屏、其他人物或随机游走全过程一致。

master 与后图使用相同 SRAM、NPC 设置、预热帧数及输入。整个 PR 也修正场景移动时钟，因此预热后的逻辑计数/显示状态自然不同；这是整个 PR 的前后比较，不是仅 NPC 提交的隔离前后比较。截图为相同 t30 / t80，文件号为 t+1，未对齐或平移帧来消除差异。

`recordings.zip` 包含原作及 master/后图的重复 PNG、状态与原作 hook/provenance；`native-verification.json` 是自动复核结果。三个提交的测试 fixture 来自原作 RAM 和截图分类，不是由待测实现生成。单元回归也在恢复中途 t60 序列化，再比较往返后连续 100 帧的 NPC/恢复状态。
