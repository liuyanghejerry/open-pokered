# 脚本步进与视口重建工作量

这是原作时钟审计证据，**没有修改生产步进代码，也没有完成原生脚本速度修复**。原作版本、受控 SRAM/输入及限制沿用 [Safari 返程](../fidelity-safari-return-148/README.md)：不证明正常付费进入或真实最后一球战斗。

原作 `home/overworld.asm` 的 OverworldLoop 连续两次 DelayFrame。SafariZoneEntranceAutoWalk 调用 StartSimulatingJoypadStates，让后续脚本方向键继续进入这一循环，而不是另设每硬件帧一次的玩家路径时钟。每格开始设置 wWalkCounter=8，立即执行 AdvancePlayerSprite；其第一次减计数还会调用 LoadCurrentMapView 和行/列重绘调度。

超时场景逐次 AdvancePlayerSprite 入口：500、503、505、507、509、511、513、515 帧；下一格 517、520、522、524、526、528、530、532；第三格 534、537、539、541、543、545、547、549。空球场景整体提前 150 帧，序列完全相同。首步跨 VBlank，随后通常隔两硬件帧推进。坐标完成时刻相隔 17 帧，当前原生仍为 8 帧。

| 调用 | 原作 CPU 工作周期 | 墙钟周期 | VBlank 中断周期 |
|---|---:|---:|---:|
| 第一格首步 | 47,828 | 61,056 | 13,228 |

测量从 AdvancePlayerSprite 可执行入口到 `.done` 的 RET 前，不含最终 RET。中断时间包含 CPU dispatch 20、vector JP 16、实际 VBlank 入口至 RETI 以及 RETI 16 周期。上述数值来自匹配原作录制；不是用 17 帧反推。

独立、有指令数上限的 LR35902 工作重放读取原作 ROM 指令和实际入口 RAM/寄存器，不模拟 PPU、不作为游戏运行时。两场景共 48 个调用：CPU 周期、全部返回寄存器、完整 tilemap/周围瓦片、滚动和坐标结果均逐项匹配。完整 sprite 数据最初检查发现第二格首步的玩家 YAdjusted 不同，失败日志保留；原因是中断中的 PrepareOAMData 从 71 改为 64。新增 VBlank 入口/RETI 读值证明该写入，重放只排除此单一中断副作用；其余 sprite 字节匹配。这不是声称重放包含全部中断副作用。

两版探针各两场景重复两次，共 5,616 张 PNG，所有 PNG 与此前有效 148 原作录制逐字节一致，帧状态也一致；新增断点仅设于可执行例程。重复试验的 events、输入/输出 RAM、寄存器和画面相同。evidence.zip 按 SHA-256 去重，MANIFEST.json 记录路径和大小；全部对象重新读出验证。work-results.json 保留逐调用结果。

下一步需要把脚本玩家路径放回共用场景循环，处理每格首步立即减计数、视口工作跨 VBlank、下一格的等待，以及 NPC/OAM 的顺序。首步工作量受地图地址/块内位置/方向等影响，实际还需要 CPU/LCD 相位，因此不能把本次 17 帧写成 Safari 专用常量，或宣称把所有路径统一乘二就已完全对齐。冠军之路 2F 第二机关、队伍恢复及其他 PR 草稿门禁依然有效。
