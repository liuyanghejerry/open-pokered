# TUI 共享运行时截图核对

基线：`deed3e23c1f360c499a1c3fe56f1482e66235e0b`。在 master 上先截旧 TUI，再在本 PR 上截相同屏幕和帧。记录的是终端半块字符转换前的实际 framebuffer。

共 44 组；32 组逐像素一致。Fusion Pixel 字体及终端显示参数保持原方案。

变化来自采用现有共享渲染：战斗菜单和城镇地图现在使用中文；图鉴采用共享边框、分隔线及文本布局。FLY 也采用共享运行时已有的八帧城镇地图离场时序。

## 复现

在仓库根目录运行（需要 gfx 资源）：

```bash
PR_SCREENSHOTS=/tmp/tui-frames cargo test -p pokered-tui capture_tui_ -- --ignored
```

新增的 `capture_tui_shared_runtime_screens` fixture 在 master 捕获时临时加到原有测试文件，使用 `crate::game::PokemonGame` 和 `dotzuki_tui::InputState`；PR 上只把这两个导入换成共享实现。屏幕设置、语言、输入序列均相同。通用屏幕的 `frame_count=180`，其余场景及帧数见测试 fixture。

像素计数按 RGBA 四通道比较；完整机器可读结果见 `comparison.json`。

## 验证结果

- `cargo test -p pokered-tui`：6 项通过（4 项显式截图测试默认忽略）。
- `cargo test -p pokered-app --lib`：150 项通过，1 项显式截图测试忽略。
- 关闭 desktop、仅启用资源和原生音频时，迁移的 16 项游戏逻辑测试全部通过。
- TUI 默认配置及 embedded-scripts/embedded-map-data 配置均构建通过。依赖树没有 winit、wgpu 或 pixels。
- 真实 PTY：输出 framebuffer 半块字符；Esc 正常退出、返回码为 0，并恢复终端。
- 场景测试 10/11 通过，包括战斗、捕获、黑屏复活、存档跨进程 CONTINUE、菜单和选项。s10 与两次 m06 流程回归均在 m03 下楼时返回二楼而失败。
- 独立 master checkout 的新编译二进制复现同一 m03 和 s10 失败：`NavError: warped out of RedsHouse1F -> RedsHouse2F`。该基线问题未计作本 PR 的通过项，本 PR 未修改导航、楼梯或共享运行时生产代码。
