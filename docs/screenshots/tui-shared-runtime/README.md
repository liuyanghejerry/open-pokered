# TUI 共享运行时截图核对

基线：`deed3e23c1f360c499a1c3fe56f1482e66235e0b`。在 master 上先截旧 TUI，再在本 PR 上截相同屏幕和帧。记录的是终端半块字符转换前的实际 framebuffer。

共 55 组；23 组逐像素一致。终端显示参数保持原方案，所有文字统一使用开源 Fusion Pixel。

采用共享渲染后，战斗菜单和城镇地图使用中文；图鉴采用共享边框、分隔线及文本布局，FLY 采用共享运行时已有的八帧离场时序。徽章标题按字体宽度居中并上移，命名列表框增加底部留白。

字体审查还覆盖战斗名称/等级/状态/HP、队伍 HP 标签、徽章编号、PK/MN、命名下划线、红蓝版本文字、GAME FREAK 文字和版权行。删除原版 PK/MN 与命名下划线嵌入字形，原版战斗文字单元及 HP 条内的标点清空。诊断截图与 GBA 使用同一开源字体规则。边框、血条、精灵、图标及 Pokémon 标志作为图形资源保留。

## 复现

```bash
PR_SCREENSHOTS=/tmp/tui-frames cargo test -p pokered-tui capture_tui_ -- --ignored
```

新增截图 fixture 在 master 捕获时临时加入原有测试文件，使用旧 TUI 游戏类与输入类型；PR 上使用共享游戏类与输入类型。两次捕获的屏幕状态、语言及输入序列相同。通用屏幕的 `frame_count=180`，其余帧数见 fixture。额外字体场景覆盖中英文、等级 100、HP 703/703、PSN、队伍、PC、命名、红蓝标题及 GAME FREAK。

战斗与狩猎区动作菜单的两行文字及光标整体上移 8px，底边上方留出至少 6px 空白；狩猎区标签按 Fusion Pixel 实际字宽绘制，BALL 与数量合为一个布局元素；不再从战斗渲染器独立插入数量。像素回归检查覆盖两种语言、两种菜单与全部四个光标位置。`battle-menu-padding-bug.png` 保存 805d8c9 上的审阅问题画面。

数量 0/1/9/10/30 的英文/中文像素检查覆盖球标签与计数，静态 GBA 布局与动态布局的输出一致。`safari-menu-width-bug.png` 保存 b7982ef 上英文拥挤的审阅画面。

像素计数按 RGBA 值逐点比较，见 `comparison.json`。
