# 背包／设置返回：背景、人物与计时交接

当前结论：**本次背景发布与人物恢复已修正，整体动画仍未完成原作对齐**。
基线为已合入的 #452（`d265e9b3`，包含 GBA 图块分配修复）。基线在背景首次恢复时
立即替换整张画面；原作分三次发布六行图块区域，人物的 OAM 发布与背景传送独立。

本次补齐分批背景、独立人物扫描、返回时的站立图像、实时传送相位，以及同一
更新内 native／IRQ 交接导致游戏时间多计一帧的问题。GBA 物理耗时仍有差距，
不能以逻辑帧或下述局部比对宣称整段动画等价。

## 原作与输入范围

原作使用 `pret/pokered@fbcf7d0e`、PyBoy 2.8.1（声音开启）及既有
`start-menu-close/fast-cancel/reference.state`。加载夹具后仅用实际按钮：
退出队伍，选择 ITEM／OPTION，停留 240 帧，再按 B 两帧。正常取消与恢复期间
短按 Down 均重复两次，连续记录首次 B 输入后的全部 80 帧。

以首次取消输入为 `t+0`，未额外停留的原作回放得到：

| 观察 | 背包 | 设置 |
| --- | --- | --- |
| `RedisplayStartMenu` / `HandleMenuInput` 入口 | t+5 | t+5 |
| VRAM 首批完成 | t+5，底部 | t+5，顶部 |
| 首批反映在已完成的画面 | t+6 | t+6 |
| 后续可见区域 | t+7 顶部，t+8 中部 | t+7 中部，t+8 底部 |
| 首次恢复玩家 OAM／画面中可见玩家 | t+6／t+7 | t+6／t+7 |

刷新顺序不是菜单的固定属性。实际多等待 0／1／2／3 帧时，原作
`LoadScreenTilesFromBuffer2` 入口的 `hAutoBGTransferPortion` 分别是：

| 额外停留 | 原作背包 | 原作设置 | 当前 native 背包／设置 |
| --- | --- | --- | --- |
| 0 | 2 | 0 | 1 |
| 1 | 0 | 1 | 2 |
| 2 | 1 | 2 | 0 |
| 3 | 2 | 0 | 1（应用回归覆盖） |

原作与 native 的菜单进入过程不同，取消前的相位也不同。比较时通过**触发前的
真实等待输入**取得相同初始相位，再逐帧比较全部 80 帧；不移动取消后的时间轴，
不挑帧、不插帧。这只证明相同初始相位下的背景发布，不证明两个进入过程或
开机状态相同。原作三种相位以及额外停留后的短按输入均各录制两次。

原作夹具目的地址为 `0x9c00`、`LCDC=0xe3`、`WY=0`、`WX=7`；菜单通过窗口
图块区显示。脚本记录两个图块区、实际目的地址、逻辑缓冲区、OAM 和窗口寄存器，
并检查最终目的区域。原作字体和菜单布局不作为像素等价标准。

## 修复路径

- #452 已执行 `LoadScreenTilesFromBuffer2` 的 360 字节复制。本次在共享总线
  接受 VRAM 写入后记录目标单元，再按 LCD 扫描行采样，只发布已完成的画面。
  未传送区域保留旧菜单，两个 native 图块命名空间不混用。
- `hAutoBGTransferPortion` 保存在共享 HRAM 投影中；native 菜单按实际 LCD
  VBlank 边沿推进，关闭 AutoBG 或 LCD 时保持。接管 IRQ 时保留该值，原作
  `LDH` 读写在各自实际指令时刻访问同一状态；不再为每次返回重置为顶部。
  老快照的未知状态只在明确的 native 初始化入口补齐，未增加恢复的原作历史。
- `HandleMenuInput::Delay3` 由同一 IRQ 连续执行；取消输入所在更新立即交接，
  不再延后一帧启动，也不在交接后叠加另一组三帧文字揭示。
- 人物使用扫描时实际硬件 OAM、对象调色板和既有图案。逻辑图像、影子 OAM、
  DMA、已扫描画面分别保留；背景区域是否完成不决定人物显示。
- 原作 `engine/overworld/movement.asm` 检查玩家脚下及 NPC 四个逻辑图块是否被
  菜单覆盖；字体加载期间恢复站立帧。本次沿此逻辑更新图像，保留位置和移动
  计数器。native 菜单覆盖范围取自实际布局，继续使用 Fusion Pixel。
- native 已处理当前更新的计时和声音时，只确认其遗留 VBlank 请求，再交给
  source IRQ。此确认不推进时钟、不伪造 IRQ 或 RETI；防止同一更新重复计时。
- 空闲扫描批处理采样所有背景行，并保留对象、窗口及最后扫描行的模式时长。
  缓存只在已发布背景、人物或调色板变化时失效；GBA 按八像素单元直接展开位面。
  native 相位计算保留延迟空闲时钟优化，不为每帧强制物化整个显示设备。

## 实际验证

Native `debug-server` 从 SRAM 冷启动 CONTINUE，经实际 START、背包／设置、B
输入验证正常取消／短按 Down，另含石英高原取消与两种额外停留，共九组输入，
每组两遍 80 帧，合计 **1,440 个连续实际帧**。每帧状态与图像两次一致；坐标、
SRAM 和最终光标保持，返回后能再次进入子菜单。

背景 ROI 按六行分区，native 取左侧 32 像素，原作取 x=56～63，避开人物、
菜单箭头和 START 文字。三种初始相位均与对应原作回放的全部 80 帧掩码一致：

| 取消时相位 | t+6 已发布 | t+7 已发布 | t+8 已发布 |
| --- | --- | --- | --- |
| 0 | 顶部 | 顶部、中部 | 全部 |
| 1 | 中部 | 中部、底部 | 全部 |
| 2 | 底部 | 底部、顶部 | 全部 |

t+0～5 保留旧背景，玩家首次可见为 t+7，START 在 t+8 可接收输入。未发布区域
保留原像素。人物检查从实际 OAM、图案和调色板解码，逐个检查不透明像素；透明
孔洞仍可看到尚未传送的旧背景，不能拿整个人物矩形与最终背景比较。

常青市最终完整画面与 #452 相同；石英高原最终差异限于 NPC 恢复站立帧
（边界 x=34～45、y=60～75）。原作、父分支和本次候选的 80 帧输入均推进
80 个游戏计时单位；修复前的同更新交接会推进 81 个。

默认 GBA release ROM 使用冷启动 SRAM、真实模拟器按键、完整渲染与音频，
不跳帧。四种输入各两遍，每次记录 800 个连续物理帧，合计 **6,400 帧**。
两遍图像、帧号和按键一致，最终完整画面等于父分支，重新打开子菜单和 SRAM
检查通过。

| 默认 GBA：首次画面变化／最终画面稳定 | #452 | 本次修复 |
| --- | --- | --- |
| 背包 | t+74／t+86 | t+84／t+97 |
| 设置 | t+90／t+102 | t+100／t+113 |

三个区域在背包 t+84／91／97、设置 t+100／107／113 发布。前后截图使用相同
原始时间点，无对齐偏移或插帧。最终稳定比父分支各多 **11 个物理帧**；
不能据逻辑帧数宣称与原作的物理耗时相同。

本地检查：核心全套 **4009 通过、1 忽略**；应用 `debug-server` 全套
**1128 通过、92 忽略**；桌面和默认 GBA 构建通过；新开局至 m06 通过（41.12 秒）。
七组 GBA 性能门限均通过，但该门限不覆盖菜单退出；菜单成本以上表独立衡量。
这轮未跑 WASM、完整主线或物理音频等价验证。

另以默认 GBA ROM 从石英高原 SRAM 冷启动，覆盖无前置菜单、图鉴、队伍、背包、
训练家资料、设置六种路径，再执行取消、短按、NO 长按、YES 长按四种 SAVE 输入，
各重复两次，共 **48 次、69,600 个连续物理帧**。所有路径均实际返回地图、重开
START，并在独立模拟器进程 CONTINUE；两遍按键、画面及 SRAM 一致，仅 YES
改变存档。未出现分配失败或 panic。重新录制的修复前画面来自已包含内存修复的
#452，而非其早期版本。原始录制只保存在本地临时目录。

## 剩余差异与复跑

GBA 菜单物理恢复耗时、原作与 native 的菜单进入过程、更多脚本人物图案和实际
音频均未达到本次完整等价结论。当前 native UI 仍为投影，不是原作开机历史。

脚本位于 [submenu-return](../../2026-11-05/submenu-return/)。原作与 native
均支持 `--case`、`--extra-idle` 并检查计时推进；native 从冷启动 CONTINUE 开始。
所有录制、运行报告、日志和清单只留在临时目录，验证后清理。仓库只保留本说明、
复跑脚本、必要测试夹具和 [四张前后截图](../../../screenshots/2026-11-12-submenu-background/)。

```sh
python replay-original.py --rom "$ROM" --symbols "$SYM" --fixture "$STATE" --case option-neutral --extra-idle 1 --output "$TMP_CAPTURE"
python replay-native.py --binary "$BINARY" --sha256 "$BINARY_SHA" --candidate --output "$TMP_NATIVE_CAPTURE"
cargo test -p pokered-app --features debug-server --lib submenu_ --locked --offline
```
