# 场外招式提示后返回队伍列表

缺少徽章、当前地点不能使用招式等情况下，原作在玩家确认提示后回到宝可梦列表，保留使用者的位置。复刻把成功和拒绝都作为 `Done` 处理，直接退出到地图。生蛋完成或选中无效目标后也走了相同的退出路径。

现在拒绝返回 `ReturnToParty { message }`，由已有 `PartyScreenState::ItemUseNotice` 单独持有提示；A/B 确认后恢复普通队伍浏览。成功的场外效果继续沿原有地图调用路径执行。生蛋结果同样在队伍界面确认后返回使用者；取消选择、普通载入、运行时快照恢复和重置会清除放弃的使用者索引，避免之后进入队伍时重开旧的目标选择。

未改变 FLASH 的成功白屏标志。飞行地图取消原本已经返回队伍，本次保留该行为，没有将它报告为缺失。

## 原作依据

引用原作 `fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c`：

- `engine/menus/start_sub_menus.asm:19` 的 `StartMenu_Pokemon.loop` 调用 `GoBackToPartyMenu`，之后检查宝可梦选择；它返回的是队伍列表。
- `newBadgeRequired`、失败的 CUT/SURF/DIG、室内 FLY/TELEPORT、生蛋的健康检查失败均跳回 `.loop`。
- 生蛋调用伪 POTION 的 `ItemUseMedicine`，恢复使用者索引，再跳回 `.loop`。`engine/items/item_effects.asm` 的成功结果绘制队伍和恢复提示，等待 50 帧及实际 A/B 确认后才返回。
- 成功的 CUT/SURF/STRENGTH/FLASH/DIG/TELEPORT 仍回到地图；飞行取消跳到 `StartMenu_Pokemon`。

实际原作只读 hook 记录每个场景的 `.loop`、`GoBackToPartyMenu` 和普通 SAVE；完整输入及截图见压缩证据。原作 ROM SHA256 为 `5ca7ba01642a3b27b0cc0b5349b52792795b62d3ed977e98a09390659af96b7b`，归档不包含 ROM 或可执行文件。

### 保留的更正与失败

[生蛋样本更正](softboiled-fixture-erratum.json) 明确旧 12 级、带 GROWL 的吉利蛋仅是引擎模型控制；原作 GROWL 在 30 级学习，正常捕获最低为 23 级。旧 4 次原作、4 次历史复刻和 4 次当前复刻结果全部保留，排除在上述最终 48 次控制之外，没有重写旧脚本或原始记录。

首个扩展原作控制器把 SURF 的显示索引误写成 3。原作表中真实 SURF 为 4，3 是未使用的 ANIM_B4；两个 dispatch 指针都指向 `.surf`。失败日志和状态保留；后续控制按真实索引完成。构造新吉利蛋时第一次使用 `DoubleSlap` 文件名拼写，实际数据为 `Doubleslap`，在启动验证前就报错；该准备错误也在更正元数据中说明。
