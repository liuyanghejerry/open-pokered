# 格子落脚后的场景按键采样

走路途中短按 START 原先立刻打开菜单，角色停在半格；途中一直按 A 又会提前消耗 A 的按下边沿，到电脑前后无法交互。候选修复在格子完成后采样场景按键：短按 A/START 丢弃，持续按住在落脚后生效，A+START 同时按下时 START 优先。狩猎结束检查仍先于菜单和交互。

普通步进完成后先处理落脚和传送，再进入下一次输入采样。NPC 跟随脚本使用正在步进的 NPC 逻辑目的格，维持大木带路的连续性。菜单返回时保留上一帧实际按键状态，使持续确认不会重触发场景交互，返回第一帧的新按键仍可识别。帧快照保存采样状态；旧 JSON 通过原有 A/B/上/下按键历史迁移。

## 原作依据

参考 `pret/pokered` 提交 `fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c`：

- `home/overworld.asm` 的 OverworldLoop 在步进期间继续 AdvancePlayerSprite，空闲后进入 JoypadOverworld；SafariZoneCheck 后检查 START，再检查 A。
- `engine/overworld/movement.asm` 的 TryWalking 在步进开始时提交 NPC 的地图目的坐标。SDK 的 NPC 状态存储步进原点直到结束，跟随脚本需要适配这个差别。
