原作 `engine/items/item_effects.asm:759` 的 `ItemUseEvoStone` 选择队员后设置 `wForceEvolution=TRUE` 并调用 `TryEvolvingMon`，没有当前 HP 检查。复刻的背包应用函数在 HP 为 0 时提前返回无效；这次移除进化石分支的这条限制，仍由已有进化动画确认物种变更并消耗一份石头。

原作实际输入采集和复刻前后采集使用可获得的等级 6 皮卡丘：HP 0/21，Thundershock/Growl、两空槽、DV `9A78`、零能力经验；另有健康的等级 6 妙蛙种子。原作 `START/ITEM/USE` 两次重复都得到雷丘 HP 3/24，攻击/防御/速度/特殊为 16/12/17/16，雷之石从 2 减至 1。这里的 HP 3 来自已有进化能力重算的最大 HP 差额，和原作相同。原作记录是实时 RAM/菜单结果，**未执行或验证原作 SRAM 保存**。

复刻成功采集包含修复前两次、修复后两次。四次使用字节相同的开机前 JSON 和相同完整输入时间表：正常 START/ITEM/USE/队员选择，第 640 帧截屏、按 B、等待进化，再通过 START/SAVE/YES 写到全新路径。不调用 debug SAVE，也没有输入期间的状态修改。修复前仍是 HP 0 的皮卡丘、石头 2 份；修复后是上述雷丘、石头 1 份，B 没有取消这次石头进化。每个版本的两次 PNG 和保存哈希一致，四个 SRAM 校验和有效，读回 JSON 与 SRAM 相符。健康伙伴、招式/PP/PP Up、经验、类型、金钱、图鉴、剧情/进度标志保持预期值。
