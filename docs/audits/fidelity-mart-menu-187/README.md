# 商店菜单与收银等待对照（187）

原作参考：`pokered` 的 `fbcf7d0e19a3a2db505440d3ccd3d40ca996c15c`，重点路径是 `home/window.asm` 的 `HandleMenuInput`、`home/list_menu.asm` 的数量选择、`engine/menus/text_box.asm` 的两选项菜单，以及 `home/inventory.asm` 的售卖收款。对照原始 ROM 输入录像与实际 native 游戏，再检查共享核心和拥有音频的前端。

## 玩家可遇到的问题和修复

- 原作普通菜单到边界停住。原先 BUY/SELL/QUIT、物品列表的 CANCEL，以及 YES/NO 会循环或反转。现在按 UP 保持最上项，连续 DOWN 保持最后项；YES/NO 不会因为重复按方向而改回相反选择。
- 原作 `HandleMenuInput` 在 A/B 确认时播放 PressAB，数量选择和离店末尾的外层确认不播放。补回这些菜单确认音，不在空闲帧重复播放。
- YES/NO 确认保留 15 帧，锁定选择并阻止输入；第 15 帧才返回交易调用者。期间钱和物品不变，重复方向和相反确认不能改选。
- 收款等待旧确认音结束，再播放收银音；音效结束前保留金额问题与数量画面，阻止再次购买或售卖。YES/NO 已恢复，成功购买的收据和错误提示不会残留该菜单。
- 售卖的数据交易一次性提交。为了保留原作收银期间可见的旧背包，使用仅供渲染的快照，不把旧物品写回背包。音效完成后恢复列表并丢弃快照，避免卖完最后一件时显示空白数量框。

英文原作 DONE/PROMPT/CONT 会话应用这些原作流程。未配置该流程的通用引擎调用和翻译后的展示路径保持既有界面；数量选择的 1↔最大值循环规则保持不变。

## 直接证据

最终 a9 CLI 在受控 Pewter Mart 场景通过真实输入完成 8 个边界场景和 7 个交易场景：上下边界、重复 DOWN 后拒绝购买、购买/售卖成功、NO/B 拒绝、不可售物品、余额不足和背包已满。每个场景录两次，所有 PNG 与 JSON 逐字节一致。`--no-audio` 仅关闭扬声器，仍使用 `Some(AudioOutput::new_pcm())`；录像记录真实音序器状态，未模拟播放标记。交易之后没有写状态。此类受控场景不是 NEW GAME 通关证据。

售卖按确认归一化的原作调用时点与 native 音频持有者均是：第 15 帧提交金额，第 17 帧开始收银音，第 34 帧恢复列表。最终实际 CLI 也通过这三个断言，等待时保留 Potion×4 的显示快照，实际背包已移除，钱只增加一次。

对购买收据额外记录原作 `PrintLetterDelay` 调用，添加钩子前后所有 PNG 与帧状态完全一致。23 个字符的逻辑写入时间全部与 native 相同：首字 +37，此后间隔 5 帧。这里验证字符写入，不声称 VRAM 分批传输后呈现帧或整屏像素与原作相同。原作显示的首字会晚于逻辑写入；该 PPU 呈现差异留在整体画面时钟审计中。

满背包的原作夹具用 ID 1..20，native 用 20 个有效物品、各 99 件；内容不同，只验证相同容量和库存堆叠已满分支。
