# 训练家只登记实际派出的宝可梦

复刻在 `start_trainer_battle` 读取训练家队伍时，把整队全部登记为“见过”。因此在 3 号道路首只小拉达处战败，也会登记尚未出场的阿柏蛇。

原作 `engine/battle/core.asm:5992–5996,6130–6140` 在 `LoadEnemyMonData` 加载当前敌人时登记 `wEnemyMonSpecies2`；通信战斗提前跳到 `LoadEnemyMonFromParty`，不执行这次登记。本修复读取唯一战斗状态 `BattleState.enemy` 的实际活动位置：训练家战斗初始化时登记首只，每次战斗更新后登记已加载的当前种族，覆盖正常替补和训练家 AI 换人。`party_mon` 保留变身前身份；不遍历整队，不复制第二份队伍，不修改野生或通信战斗的登记路径。

## 回归与边界

- 最新 debug-server 应用专项 **4通过**；完整应用 **282通过、39忽略、0失败**。
- 默认特性应用专项 **4通过**。
- 回归覆盖首只登记、真实 `post_text_transition` 派出后续敌人、Transform 的原始队伍身份、通信与野生路径不新增登记。
- 通信及 Transform 只做了单元/静态检查，没有冒充实际双端通信或实际 Ditto 对照。野生幽灵的登记差异不在本修复中。
- 只验证 Red 上述三场景，不宣称所有训练家、完整通关或逐帧/音频等价。整份剧情模板是构造输入；只对已列宝可梦数据和场景断言负责，不声称整个模板自然可达。

原作 AI 第一版脚本错误地要求最终胜利，实际自然战斗以战败结束，因此没有计入最终6次；失败日志、已有原始画面与脚本保留。第二版接受实际结束结果并以普通 SAVE 读回图鉴。无效记录没有重标为通过。

`verification.json` 为简明结论，归档中的 `audit-906-verification-full.json` 保存逐个 SRAM、检查点和哈希。`evidence.zip` 对相同内容按 SHA256 去重，保留所有原始路径与原始字节；运行 `python3 extract_evidence.py evidence.zip --verify-only` 可独立校验。ROM/可执行文件不入库，精确哈希与构建源码清单保留；只在运行终结后删除冗余 ROM/可执行副本，原始状态、SRAM、输入、PNG 和失败日志不删除。
