# 联机交换：取消入口与确认时序（58、60–63）

对照原作 `engine/link/cable_club.asm` 的 `TradeCenter_SelectMon`、
`.cancelMenuItem_JoypadLoop`、`.choseTrade` 和 `CableClub_Trade`。

## 玩家可遇到的问题

- 58：队伍列表原来循环滚动，用 B 取消；原作上下不循环，B 无效，底部有双方共享的 CANCEL。CANCEL 只接受 A/上，A 优先；上返回自己队伍最后一只。
- 60：列表 CANCEL 对上选宝可梦时，错误显示确认拒绝台词。原作此处只重新显示列表。
- 61：确认 NO 和列表 CANCEL 共用状态，之后对方取消会误判双方退出。
- 62：先收到对方 CANCEL、再自己选择 CANCEL 时，只退出一方，另一方永久等待。保留对方选择，直到本方提交；双方 CANCEL 都退出，CANCEL 对上宝可梦继续选择，清除双方旧索引。收到 CANCEL 不打断正在查看的状态页。
- 63：一方 YES、另一方 NO 时，过早发送的宝可梦数据会触发预览不匹配错误。原作双方确认后才交换。现在本地数据等待双方 YES，NO 清除暂存数据，队伍保持不变。

确认 NO 使用独立网络消息 `RejectTrade`，协议版本升至 4，旧协议在握手阶段拒绝，避免交换中途解析未知消息。

## 验证

原生测试用两台 `PokemonGame` 和真正的 `ChannelTransport`，从桌前 A、握手和接受请求开始，使用实际按钮推进，不注入交易阶段。覆盖不循环、B 无效、CANCEL 输入优先级、先后取消、状态页不被打断、旧选择清除、NO 后再取消、YES/NO 竞态和队伍不变。
